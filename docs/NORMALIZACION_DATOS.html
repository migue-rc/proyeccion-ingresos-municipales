Normalización presupuestaria al contrato 2025

Objetivo

Todos los archivos Excel de data/ se cargan mediante un único contrato de columnas basado en la estructura 2025. La API no permite escoger otro esquema: el resultado de data_loader() siempre usa canonical_schema_version == "2025".

El proceso separa tres conceptos que no deben confundirse:

  1. Dato fuente: códigos, nombres, archivo y número de fila originales.
  2. Dato canónico: nombres de columnas, tipos, municipio y servicio según la convención 2025.
  3. Grupo analítico: homologación excluyente del ingreso a uno de los seis grupos utilizados por los gráficos.

Uso recomendado

from utils.data import (
    build_presupuesto_monthly,
    data_loader,
    get_normalization_report,
)

# La misma llamada funciona para cualquier comuna del catálogo 2025.
presupuesto = data_loader(municipality="Renca")

# Revisar qué se reconstruyó y qué reglas históricas requieren revisión.
reporte = get_normalization_report(presupuesto)
print(
    reporte[
        [
            "source_file",
            "years",
            "review_income_rows",
            "unmapped_municipality_rows",
            "cache_status",
        ]
    ]
)

# Formato largo para análisis temporal mensual.
presupuesto_mensual = build_presupuesto_monthly(presupuesto)

También se puede limitar la carga por ejercicio o forzar su reconstrucción:

presupuesto = data_loader(
    municipality=8728,
    years=range(2008, 2026),
    refresh=True,
)

municipality acepta el nombre o el código canónico. Filtrar en la carga es recomendable para notebooks de una comuna porque reduce considerablemente la memoria del DataFrame resultante.

Flujo de normalización

utils/data.py realiza estas etapas en orden:

  1. Lee todos los .xlsx y normaliza alias históricos de columnas.
  2. Conserva la jerarquía original en columnas source_*.
  3. Convierte códigos a Int64, valores monetarios a Float64 y textos a string.
  4. Reconstruye totales anuales ausentes a partir de sus componentes mensuales.
  5. Homologa los servicios a Gestión Municipal, Educación, Salud o Cementerios.
  6. Clasifica cada ingreso de Gestión Municipal en un grupo canónico.
  7. Reemplaza nombre, código y región del municipio usando el catálogo 2025.
  8. Valida el contrato antes de concatenar los años.

La lista de columnas canónicas y sus tipos está centralizada en utils/data_schema.py. El archivo 2025 es también el catálogo de identidad municipal. Algunas grafías históricas conocidas, por ejemplo LLAY-LLAY, MARCHIGUE, TREHUACO y QIQUEN, se resuelven mediante alias explícitos.

Homologación de ingresos

El campo grupo_ingreso_canonico contiene exactamente uno de estos valores para cada ingreso de Gestión Municipal:

  • Transferencias corrientes
  • Transferencias de capital
  • Otros ingresos
  • IPP
  • FCM
  • Recaudación para terceros

Los primeros cinco grupos componen el Total disponible utilizado por el pronóstico. Recaudación para terceros se conserva como sexto grupo para el análisis contable, pero se excluye del total porque corresponde a recursos que deben remitirse a otro beneficiario.

Desde 2008 se utilizan los códigos modernos definidos en utils/ip_keys.py. IPP y FCM tienen prioridad sobre el subtítulo general para que cada fila sea mutuamente excluyente.

Entre 2002 y 2007 la jerarquía contable no es equivalente uno a uno con 2025. Por esa razón:

  • los códigos originales se conservan como source_cod_*;
  • los campos detallados canónicos de cuenta quedan nulos, evitando presentar un código antiguo como si fuera moderno;
  • las equivalencias exactas se versionan en utils/crosswalks/legacy_income_groups.csv;
  • las reglas de texto complementarias están en utils/income_mapping.py;
  • las transferencias históricas cuya naturaleza no es inequívoca se marcan con income_mapping_status == "review".

Agregar una regla histórica requiere modificar el CSV o la regla explícita, incrementar NORMALIZATION_VERSION y ejecutar las pruebas. El caché se invalida automáticamente cuando cambia el crosswalk.

Columnas de auditoría

Las columnas principales para revisar una homologación son:

Columna Propósito
source_file, source_row Ubicar la fila en el Excel original.
source_schema_version Distinguir formato legado de moderno.
source_* Preservar códigos y nombres antes de homologar.
municipality_mapping_status Explicar cómo se resolvió el municipio.
service_mapping_status Explicar cómo se resolvió el servicio.
income_mapping_status Indicar mapped, review o not_applicable.
income_mapping_method Identificar código, crosswalk o regla textual.
normalization_version Reproducir la versión de las reglas aplicadas.

get_normalization_report() entrega indicadores por archivo, incluidos filas sin municipio, servicios no reconocidos, ingresos sin grupo y reglas en estado de revisión.

Validaciones y garantías

Con validate=True, valor predeterminado, la carga falla si:

  • el Excel introduce una columna sin una regla explícita de normalización;
  • falta una columna del contrato;
  • aparece una versión canónica diferente de 2025;
  • queda un ingreso de Gestión Municipal sin grupo;
  • queda un municipio sin correspondencia en el catálogo 2025.

Los servicios no reconocidos se cuentan en el reporte, pero no detienen por sí solos la carga: pueden corresponder a registros fuera del alcance de Gestión Municipal. Los años incompletos se detectan después de cargar mediante infer_year_coverage(): diciembre con actividad se considera completo, un último mes anterior se considera parcial y la ausencia de evidencia mensual se considera desconocida.

Caché local

Cada Excel normalizado se guarda en data_normalized/schema_2025/ como pickle comprimido con gzip, junto a un manifiesto JSON. El directorio está ignorado por Git y se debe considerar un caché local confiable: pickle no debe cargarse desde fuentes externas.

El manifiesto invalida el archivo cuando cambia cualquiera de estos elementos:

  • tamaño o fecha de modificación del Excel fuente;
  • archivo 2025 utilizado como catálogo municipal;
  • crosswalk histórico;
  • NORMALIZATION_VERSION.

Use data_loader(refresh=True) para reconstruirlo manualmente. La primera carga aparece como rebuilt y las siguientes como hit en el reporte.

Incorporar archivos nuevos

  1. Copiar el .xlsx a data/ con el ejercicio de cuatro dígitos en el nombre.
  2. Ejecutar data_loader(refresh=True).
  3. Revisar get_normalization_report() y exigir cero en missing_income_group_rows y unmapped_municipality_rows.
  4. Inspeccionar cualquier fila informada en review_income_rows usando source_file, source_row y las columnas source_*.
  5. Ejecutar python -m unittest discover -s tests -v.

No se debe agregar un selector de esquema. Si el archivo introduce una variante nueva, se agrega un alias o una regla de homologación para mantener el contrato 2025 como única salida pública.
